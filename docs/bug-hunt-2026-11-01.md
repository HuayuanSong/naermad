# Independent bug hunt — 1 November 2026

Review base: `b30f4a5`. Three independent reviewers examined UI/asynchronous
behavior, inventory/pricing, and Worker/API boundaries. Their first passes were
read-only. Confirmed findings were reproduced before applying narrow local fixes.

## Confirmed findings

| Priority | Reproduction and impact                                                                                                                                                | Local correction                                                                                                                                                       |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P2       | Select a non-nearest store and press refresh: the app silently switches to the nearest store.                                                                          | Refresh carries the selected store ID through the fetch, retaining it when present and falling back when it disappears. Other location searches retain their behavior. |
| P2       | `Kartofler 1 500 g` is parsed as a 500 g pack, producing a confidently overstated purchase quantity. Ordinary, nonbreaking and narrow nonbreaking spaces reproduce it. | Reject a partial match preceded by another numeric token; use the existing estimated-quantity path.                                                                    |
| P2       | `Yoghurt 4-pak 125 g`, `4 pak` and `4-pack` treat the inner container weight as the whole sale unit.                                                                   | Treat unsupported pack-count wording as unknown. Explicit `4 x 125 g` multiplication remains supported.                                                                |
| P3       | 350 g at DKK 3.30/kg rounds to 115 cents instead of 116 under the existing half-up rule.                                                                               | Calculate with integer grams and integer price cents before division and final rounding, including edited quantities.                                                  |
| P2       | An unrelated earlier negation lets a washing instruction through the existing narrow meat-washing guard.                                                               | Require an attached prohibition, including genuine English/Danish prohibitions and coordinated washing verbs. Reminder phrases do not exempt the instruction.          |

The refresh cache policy is preserved: the five-minute cache and rate-limit
handling still govern requests. Refresh does not promise a new upstream request.
The selected-store fix does not increase stock API usage.

Ambiguous packs retain the existing editable one-sale-unit estimate; their size is
not guessed. These label cases are synthetic examples, not measurements of their
prevalence in Salling inventory. Purchase totals still exclude extra ingredients
and pantry items.

The output guard repairs a specific observed failure class. It is not general
natural-language understanding, food-safety verification or dietary verification.
Review of the first fix caught false rejections of genuine prohibitions; additional
regressions now cover those phrases as well as the original false acceptances.

## Validation

- Five failure cases were demonstrated before their corrections. Six new tests
  cover these findings plus the missing-store fallback; existing prohibition tests
  were expanded.
- 45 unit/API tests and 25 browser tests pass. Browser coverage includes manual and
  inspiration modes, both languages, cancellation, costs, downloads, mobile layout
  and automated accessibility checks.
- Lint, formatting of changed files, diff checks, the frontend build and Worker
  packaging dry-run pass. Four saved recipe/ideas prompt and schema comparisons
  remain identical.
- Reviewers checked the fixes in their respective areas. No other confirmed issue
  was established in this bounded pass.

The Worker review also exercised 34 malformed input cases and 18 malformed provider
responses/exceptions using fixtures. This checks rejection and redaction behavior,
not the deployed model or platform under load.

The review and fixes were prepared locally without live stock requests or model
inference. Model selection, prompts, JSON schemas, provider settings, caching,
request allowances and deployment configuration are preserved. The subsequent
publication is recorded in [verification](../VERIFICATION.md#independent-bug-hunt).
